# Changelog

## Unreleased (v1.0.0, hard break)

- **A fresh full-JAX core (`tinyns/core.py`).** `Config(ndim, nlive=1000, num_delete=None, walks=None)`, the `State` and `Dead` pytrees, `init`, `step`, `finalise`, `delta_logz` and the driver `run`. Each step deletes the `num_delete` lowest live points (default `max(1, nlive // 10)`) and replaces them with fixed-length constrained random walks (no retry loop; an unmoved chain returns its seed), seeded without replacement above `L*`. The step-scale adaptation runs inside `step`. With `num_delete=1` the chain is not vmapped and out-of-cube proposals skip the likelihood; otherwise all lanes are evaluated and `metadata["ncall_valid"]` counts the in-cube ones.
- **Evidence with several deaths per step** (birth/death contours): live counts `m, ..., m-k+1` per step and `m, ..., 1` for the final live points; `finalise` recomputes the weights, `logz` and `logzerr = sqrt(sum_i dH_i / n_i)` in float64. The last sample takes the remaining prior volume, so a constant likelihood gives its value exactly. `result.nlive_i` and `result.num_delete` are new; the insertion test ranks new points among the `nlive - num_delete` survivors of their step. Result `.npz` files are `tinyns-result-npz-v3`.
- **Driver.** A jitted `lax.while_loop` runs chunks of up to four e-folds of steps into a preallocated dead buffer; `n_steps`, `dlogz`, `maxiter` and `maxcall` are traced, and the host syncs once per chunk (chunks grow to about 45 s). `maxcall` is new; a likelihood plateau ends the run with status `plateau`.
- **API.** `NestedSampler(loglike, prior_transform, ndim, nlive=1000, *, num_delete=None, walks=None).run(key, *, dlogz=0.1, maxiter=None, maxcall=None, progress=False)`. Exports: `NestedSampler`, `Config`, `init`, `step`, `finalise`, `NestedSamplingResult`, `LogZBootstrap`.
- **Removed:** `block_size`, `replacement_chains`, `cluster_swap`, `callback`, `checkpoint_path` and `resume` (checkpoints return in the next PR, in a new format), `tinyns/loop.py`, `tinyns/types.py`, `tinyns/checkpoint.py`, `benchmarks/`, `tools/ab_bitwise.py` and the `ab-bitwise` CI job. Numerics change on purpose: no result is bit-identical to v0.x.
- **`modes()` no longer splits a curved unimodal posterior.** Replacement chains get stuck in the narrow tips of a Rosenbrock banana, and the seed copies and short moves they return leave clumps of near-identical live points there, 7 to 50 deviations from the bulk along the discriminant. The split test cut these clumps off and the gap test kept them as modes, flagged unresolved: 26 of 384 runs of the 5-D and 10-D bananas at nlive 500 and 1000 (x64 off and on, 48 seeds each) reported two modes. A cluster with at most `ndim` distinct live points at its own posterior median is now dropped (its samples go to the nearest remaining cluster), since so few points span no volume, and the gap counts repeated points once. All 384 runs now report one mode and no warning. Detection is unchanged on two-mode targets: a 6% minor mode at 4-D, nlive 500, is found in 96 of 96 runs (minor mass 0.031-0.107), and the 25% mode of the 3-D test target at nlive 400 in 85 of 96, as before. The k-deletion `n(t)` and birth reconstruction were checked: the live count at every death equals `nlive_i`.

## Unreleased (v0.3.0)

The live-cov walk does not need bounds, bound seeding did not fix mode-weight drift, and `cluster_swap` handles separated modes. The bound entries of `result.metadata`, of the callback state and of the checkpoint config and telemetry are gone too, as are the bound options of `benchmarks/bench_static.py` and `--include-bounds` of `benchmarks/overnight_jax_validation.py`. The default path is bit-identical to v0.2.5.
- **Unknown keyword arguments raise `TypeError`**: `NestedSampler` used to store and warn about them (a dynesty drop-in leftover). The message suggests the closest known name, e.g. `walk` -> `walks`. Removed options such as `bound` raise the same way.
- **Removed every non-default sampling path.** What remains is the default: the live-cov random walk, run as a pure-JAX kernel in jitted blocks, plus the cluster swap. Its numbers are unchanged: fixed-seed runs are bit-identical to the previous `main` on CPU with x64 on and off (`tools/ab_bitwise.py`). `loglike` and `prior_transform` must be JAX-traceable scalar functions of one point. The constructor is now `NestedSampler(loglike, prior_transform, ndim, nlive=500, *, walks=None, replacement_chains=1, block_size=32, cluster_swap=None)`; `run` and `resume` are unchanged. Removed keyword arguments (they raise `TypeError` like any unknown keyword):
  - `kernel` (`"python"`): the sampler is pure JAX. The python kernel and its helpers are gone (`draw_constrained_rwalk`, `_evaluate_live_points`, `_transform_live_points`, `_as_point(s)`).
  - `sample` (`"prior"`): the brute-force constrained-prior sampler was a reference baseline only (`draw_constrained_prior`, `draw_constrained_prior_vectorized`).
  - `vectorized`, `jax_vectorized`: tinyns vmaps a scalar `loglike`.
  - `rwalk_proposal` (`"isotropic"`): the isotropic step stalls at d >= 4; live-cov is the only proposal. `tinyns.math.reflect_unit_cube` is gone too.
  - `step_scale`, `rwalk_adaptive_step_scale`, `rwalk_target_accept`: the scale always starts at 0.5 and adapts toward 25% acceptance after every block.
  - `min_accepts`: always 0. The retry rule biased minor modes and logZ (v0.2.4).
  - `max_attempts`, `batch_size`: a fixed-length walk seeded above the threshold cannot run out except on a likelihood plateau. A replacement still retries its batch up to `10_000 // (walks * replacement_chains)` times (at least once); when every batch fails, the run stops with `success=False` and the message `replacement failed at iteration N: ...`.
  - `replacement_chain_schedule`: adaptive chain schedules ran only on the per-iteration loop, which is gone; a fixed `replacement_chains` remains.
  - `jax_block_size` is renamed `block_size` (no alias). `block_size=1` now runs through the block kernel (one iteration per block, with the cluster swap available).
- **Removed the per-iteration loop and the rescue ladder.** Every run goes through the jitted block kernel. A failed replacement no longer retries with smaller steps and longer walks (the `replacement_rescue_*` metadata and telemetry are gone); the run stops as above, after writing a final checkpoint.
- **Metadata.** Gone: `sample`, `kernel`, `rwalk_proposal`, `step_scale`, `min_accepts`, `batch_size`, `jax_vectorized`, `jax_block_mode`, `jax_block_cached`, `jax_block_kernel`, `jax_block_impl`, `replacement_chain_schedule`, `adaptive_replacement_chains`, `replacement_initial_batch_ncall`, `replacement_max_batch_ncall`, `mean_replacement_chains_used`, `max_replacement_chains_used`, `replacement_chain_usage_counts`, `mean_total_replacement_calls` (it equalled `mean_replacement_ncall`), `rwalk_adaptive_step_scale`, `rwalk_target_accept` and `rwalk_observed_accept_source`. Renamed: `jax_block_size` -> `block_size` and `rwalk_effective_step_scale_{initial,final,min_seen,max_seen,mean}` -> `rwalk_scale_{...}`. The callback state and the progress line lose `sample`, `kernel` and the chain-usage fields.
- **Checkpoints.** The config handshake is `ndim`, `nlive`, `walks`, `replacement_chains`, `block_size` and `cluster_swap`; a missing or different key raises `ValueError`. Checkpoints written before this change are not read (`_OLD_CHECKPOINT_DEFAULTS` is gone). The step scale is stored as `scale` (was `effective_step_scale`). The format is otherwise unchanged until the v2 checkpoint.
- Examples, benchmarks and the validation harness run the default sampler. Removed: `examples/gaussian_2d_rwalk.py`, `examples/gaussian_2d_rwalk_jax.py`, `examples/vectorized_gaussian_2d.py` and `benchmarks/bench_rwalk_kernel.py`. `bench_static.py`, `overnight_jax_validation.py` and `validation/run_validation.py` take `--walks`, `--replacement-chains` and `--block-size` (`--block-sizes` for the overnight harness, one configuration `live_cov_B<size>` each) instead of the sampler-selection options.
- **Internal: a pure-JAX `init`/`step` core.** `tinyns/core.py` holds `Config` (hashable, static: `ndim`, `nlive`, `walks`, `replacement_chains`, `block_size`, `cluster_swap`), the `State` and `Dead` pytrees (NamedTuples of arrays), `init` (the initial live-point pass), `step` (one jitted block of `block_size` iterations) and `remaining_dlogz`. `tinyns/callables.py` holds the pytree partition of the callables, the closure-constant hoisting and the structure-keyed kernel caches. `tinyns.samplers` is gone. `run_static_nested` is the host loop over `core.step`. Fixed-seed results are bit-identical to the previous `main` with x64 on and off (`tools/ab_bitwise.py`).
- **Internal: the cluster swap is a host hook.** `clusters.ClusterTracker` is the loop's only view of the swap: `before_block(state, dead) -> extras | None` (the cluster frames for `core.step`, or `None` while fewer than two clusters can swap), `after_block(state, block)` (counts the swaps and takes them out of the rwalk `moves`/`proposals`), `state_dict()`/`load_state_dict()` (the checkpoint's `ext/clusters/` entries) and `summary()` (the `cluster_*` metadata, `cluster_host_s` included). `loop.py` keeps no swap bookkeeping of its own. Fixed-seed results, metadata and checkpoints are bit-identical.
- **`result.logl_birth`**: the likelihood contour each sample was born above, aligned with `logl` (`-inf` for initial live points). It is saved by `save_npz`, included in `to_dict`/`to_numpy`, and checkpoints carry it (`state/birth`, `dead/birth`), so a resumed run has it too.
- **The `maxiter` tail reuses the compiled block.** `core.step(..., n_active=k)` runs the first `k` iterations of a block in the same compiled program (`n_active` is traced); the host loop no longer compiles a second, shorter block when `maxiter` falls mid-block. Outputs are unchanged.
- **Plain-Python-float and float32 likelihoods work under `JAX_ENABLE_X64`.** They failed with `true_fun and false_fun output must have identical types`: a weakly typed (or float32) `logl` made the block's `logwt` float32 while the skip branch gave float64. The kernels now cast the likelihood output to the default float dtype, which is the live `logl` dtype. Outputs of every likelihood that already ran are unchanged.
- Checkpoint telemetry keeps running totals `rwalk_moves`/`rwalk_proposals` instead of the per-iteration `rwalk_accepted_move_history`/`rwalk_proposal_history` lists, and drops `adaptive_updates` (it equalled the length of `adaptive_accept_history`).
- **Checkpoint format v2 (`tinyns-ckpt-2`).** A checkpoint is one `.npz` file, written atomically (a temporary file, then `os.replace`), with `format = "tinyns-ckpt-2"`; the `core.State` leaves under `state/<field>` (the PRNG key as raw `uint32` key data, with its implementation in `state/key_impl`, so typed `jax.random.key` keys and legacy `uint32` keys both round-trip exactly; `state/scale` is the host step scale); the dead rows under `dead/<column>` (`u`, `theta`, `logl`, `logwt`, `birth`, `ncall`, `batches`); `config_json` (the resolved `ndim`, `nlive`, `walks`, `replacement_chains`, `block_size`, `cluster_swap`, plus `tinyns_version`); `telemetry_json` (`rwalk_moves`, `rwalk_proposals`, `wall_time_s`, `compile_s`, `timed_ncall`); and the cluster tracker's state under `ext/clusters/` (`log.json`, `labels`, `u`). Resume loads the state, the dead rows and the hook state and continues in the same host loop; the six config keys are compared and a mismatch raises `ValueError` naming the key. The callables cannot be checked. A run killed and resumed at any block boundary is bit-identical to an uninterrupted one, metadata included (tested with x64 on and off, with the cluster swap active). The code is `tinyns/checkpoint.py`; `tinyns/state.py` and `NestedRunState` are gone.
- **Old checkpoints are not readable.** Files written before v0.3 (`tinyns-checkpoint-npz-v1`) raise `ValueError("not a tinyns-ckpt-2 file ...")`. There is no converter: finish in-flight runs on the version they started on.
- **Result (v0.3 PR 6).** Sampling is unchanged: fixed-seed samples, `logz`, `logzerr` and `ncall` are bit-identical to the previous `main` (`tools/ab_bitwise.py`, x64 on and off).
  - `NestedSamplingResult` is a keyword-only dataclass with two new required fields: `logl_birth` (the likelihood contour each sample was born above, `-inf` for the initial live points) and `niter` (the number of iterations, i.e. dead points; the samples are the `niter` dead points, then the final live points). The `.npz` format is `tinyns-result-npz-v2` (it stores both); `tinyns-result-npz-v1` files are not read.
  - `res.insertion_indices()` is rebuilt from `logl_birth` (replaying the deaths and births on the sorted live likelihoods) instead of read from metadata: the rank of each new point among the other `nlive - 1` live points, uniform on `0..nlive-1` for a correct sampler. It equals the in-kernel ranks exactly.
  - `res.insertion_test(windows=3)`: a Kolmogorov-Smirnov test of the insertion indices against the discrete uniform law, pooled and in `windows` equal stretches of the run (a bias in part of the run is not diluted by the rest). It returns `n`, `ks`, `pvalue` and the same per window under `windows`. It replaces `insertion_rank_mean_z` and `insertion_rank_std_ratio`; `diagnostics()` warns when the smallest p-value times the number of tests is below 0.01.
  - **Per-mode diagnostics**, `res.modes()`: pure post-processing that works with the cluster swap on or off. An equal-weight draw of the posterior is clustered with the cluster swap's split test, every sample is labelled by its nearest cluster, and each mode's live count `n(t)` is rebuilt from the birth and death iterations. The split test also cuts a single curved mode (a banana) into linear pieces, so two clusters count as separate modes only if, at the earlier of their posterior medians, their live points leave a gap of `SEPARATION_SIGMA = 3` within-cluster standard deviations along the discriminant direction; touching clusters are merged (5-D and 10-D Rosenbrock bananas at nlive 500: one mode in 8/8 seeds each, where up to 3 were reported before; separated modes leave gaps of 22-32). A mode is isolated from the first iteration at which its live points and the rest pass the split test. Each mode reports `mass`, `urn_sd` (the seed scatter of `logit(mass)` from the random walk of `n(t)` between isolation and the posterior medians, section 7 of the multimodal study: `1/n + 1/(N - n)` at isolation plus `2 (1 - g) / (N^2 g)` per iteration up to the mode's median and `2 g / (N^2 (1 - g))` up to the rest's; an upper bound with the swap on), `min_live` (the smallest `n` between isolation and the mode's median), `isolation_iteration` and `unresolved` (`min_live < UNRESOLVED_PER_DIM * ndim`, with `UNRESOLVED_PER_DIM = 3`: the population below which the mass is not reliable; raise `nlive`). A unimodal run gives one mode of mass 1. `summary()` (now also `str(res)`) prints a per-mode table when there are several modes, `diagnostics()` carries `modes` and warns about each unresolved one. A mode lost before the end of a run leaves no trace in it. On the two-mode 4-D target with a 6% minor mode (nlive 500, 8 seeds), the reported minor mass is 0.051-0.072 with the swap (mean 0.063), `urn_sd` 0.49-0.55 and `min_live` 26-39 (resolved); without the swap it scatters from 0.012 to 0.11 with `urn_sd` 0.44-0.66, and the 1.2% seed is flagged (`min_live` 7). At nlive 100, 7 of 8 seeds are flagged and the eighth lost the mode.
  - `metadata` is cut from 64 keys to 13, plus 4 `cluster_*` keys with the swap on: `walks`, `replacement_chains`, `block_size`, `cluster_swap`, `dlogz`, `acceptance` (rwalk move acceptance over the run), `scale_initial`, `scale_final`, `wall_time_s`, `compile_s`, `mean_ms_per_call`, `final_delta_logz`, `resumed`; with the swap, `cluster_count_history`, `cluster_swap_accepts`, `cluster_swap_proposals` and `cluster_host_s`.

## v0.2.5 (2026-10-02)

- **New default on the fast path**: `cluster_swap=True`. Mode weights of separated modes no longer drift with the seed when each mode is large enough. Replacement chains start from live points and cannot cross between separated modes, so each mode's live count did a random walk. On a real 18-D posterior with a 16% minor mode, two seeds gave 7% and 32%. tinyns now clusters the live points on the host between blocks and tracks the clusters across blocks. Once two clusters each have a volume share that predicts at least 2 x `ndim` live points, a tenth of the chain steps become an affine swap `u' = mu_b + L_b L_a^-1 (u - mu_a)` into another cluster's frame. The swap is accepted when `u'` is in the cube, above the threshold and nearest to frame `b`, with the Metropolis factor `det L_b / det L_a`. This is exact for any frames. The frame of the chain's seed is refit without the seed, and the rwalk keeps the global live covariance.
- Measured with tinyns on two-mode Gaussian targets with a 6% minor mode (nlive 500, 20 seeds per cell, swap off -> on). Logit seed scatter of the minor-mode mass: 0.46 -> 0.15 and 0.36 -> 0.10 at 4-D (two minor-mode shapes), 0.83 -> 0.16 at 10-D, 1.28 -> 0.39 at 18-D (200 seeds; the prototype gives 0.36 there). Mean mass with the swap on: 0.060, 0.060, 0.057 +/- 0.002 and 0.058 +/- 0.001. An eligibility threshold of 3 x `ndim` switched the swap off too early at 18-D (0.52, 40 seeds, one seed lost the mode). logZ bias and scatter are unchanged, and likelihood calls fell by 2% to 5%. A minor mode with fewer live points than about 2 x `ndim` (20 at 10-D, 36 at 18-D) gets no reliable benefit: the swap stays off or flickers, and the weights drift as before.
- On a real 18-D posterior (darksirens rung 5, BPL+2G, low-H0 mode holding 18-22% of the mass by a split-prior reference) at nlive 1000, 8 seeds per arm: the swap gives a low-H0 mass of 0.188 on average (logit sd 0.30) against 0.135 (logit sd 0.44) without it, and logZ -678.45 +/- 0.23 against the reference -678.3 +/- 0.2. At nlive 500 both arms come out near 0.08: the mode holds only about 28 live points (1.5 x `ndim`) when it is first detected, too few for the swap.
- A unimodal run that the clustering does not split is bit-identical to v0.2.4 for the same seed; a test pins fixed-seed fingerprints. On synthetic single ellipsoids, uniform boxes and the 13-D Gaussian there were no false splits. Real posteriors do get split sometimes: 3 of 10 seeds on a 13-D mock spectral-siren fit and 2 of 2 on another, none on a 16-D dark-siren fit. The move is exact either way, and those runs agree with v0.2.4 and the reference within `logzerr` (13-D means -58.578 vs -58.581, reference -58.623 +/- 0.029). The clustering runs on the host and never touches the PRNG stream. It costs about 12 ms per update at 13-D (one update every 128 iterations): 2.0 s of a 29 s run on a 13-D Gaussian.
- `result.metadata` reports `cluster_count_history` (`[iteration, clusters]` at each change), `cluster_swap_proposals`, `cluster_swap_accepts`, `cluster_min_population` and `cluster_modes`. `cluster_modes` gives, for each mode, its mass, its smallest live count between detection and its posterior median, and `urn_logit_sd`, the seed scatter of `logit(mass)` the drift would cause without the swap. Also `cluster_host_s`.
- `cluster_swap` applies to `sample="rwalk"`, `kernel="jax"`, `bound="none"`, `rwalk_proposal="live-cov"`, `replacement_chains=1` and `jax_block_size > 1`. Elsewhere it defaults to False, and an explicit `cluster_swap=True` raises `NotImplementedError`. Checkpoints record it and the cluster tracker's state. A checkpoint without the key reads as `cluster_swap=False`, so resume a v0.2.4 checkpoint with `cluster_swap=False`.

## v0.2.4 (2026-10-02)

- **Changed default**: `min_accepts=0` (was 1). A replacement chain that never moved is now kept as a copy of its seed, instead of being discarded and retried. The retry rule was biased: chains fail to move more often where the proposal fits poorly, so retrying under-sampled those regions. Measured with tinyns itself on two-mode Gaussian targets with a true 6% minor mode (nlive 500): at 4-D the old rule gave 2.9% +/- 0.3% and a logZ bias of +0.13 +/- 0.03, the new default 6.3% +/- 0.4% and +0.02 +/- 0.03 (40 seeds each); at 10-D, 1.7% +/- 0.6% against 6.7% +/- 1.7% (18 seeds each). Call counts are unchanged. A kept chain must still end inside the constraint, and an unmoved chain only counts if its seed is strictly above the threshold. Pass `min_accepts=1` for the old behaviour; checkpoints written with the old default need `min_accepts=1` to resume.

## v0.2.3 (2026-10-01)

- A loop over mock datasets no longer recompiles for every dataset. The fast-path kernel caches (block kernel, rwalk kernel and the initial live-point pass) were keyed on the identity of `loglike` and `prior_transform`, so each `jax.tree_util.Partial(loglike_fn, data_i)` built and compiled a new block kernel. They are now keyed on the callable's structure: a pytree callable's treedef and static leaves, with its array leaves passed as jit arguments, so JAX's jit cache keys the compiled program on their shapes and dtypes. On CPU, four `Partial` datasets of the same shape (1-D, 10k points, fixed `maxiter`) took 2 backend compiles for every new dataset in v0.2.2 (block kernel and live-point pass) and none in v0.2.3. Each result is bit-identical to a fresh run on that dataset. The live-point pass is now cached too; v0.2.2 compiled it again on every run, even for the same callable.
- Finished runs no longer keep their datasets alive. The `lru_cache(maxsize=32)` held up to 32 callables and so their data: in a four-dataset probe, v0.2.2 retained all four. The caches now hold no array leaves. Closures and plain functions are cached by identity through weak references, and their hoisted constants are dropped when the closure is garbage collected, so a dataset is freed once you drop it. Each closure object still compiles its own kernels; use a pytree callable to share one compile across datasets.
- Plain functions and small closures give bit-identical results to v0.2.2: a test pins fixed-seed `logz`, `samples`, `samples_u`, `logl` and `ncall` for the block and per-iteration paths. `Partial` and hoisted-closure runs were also checked to be bit-identical.
- `result.metadata` reports wall-time telemetry: `wall_time_s` (sampling wall time of the call), `compile_s` (time to the end of the first block, which carries the compiles) and `mean_ms_per_call` (wall time per likelihood call after the first block). Progress lines show `calls/s` since the first block, and callback states carry `calls_per_s`. There are no new arguments.
- The README notes that separate processes in a campaign can share compiles through JAX's persistent cache (`jax.config.update("jax_compilation_cache_dir", path)`). On CPU, a second process with a different dataset read its compiled programs from the cache and reached the end of its first block in 0.72 s instead of 1.62 s.

## v0.2.2 (2026-10-01)

- With the default single chain (`replacement_chains=1`), a live-cov proposal that leaves the unit cube no longer calls the likelihood. It is rejected either way, so it now takes a `lax.cond` branch that returns `-inf` without evaluating. `ncall` counts likelihood evaluations actually made; the acceptance rate and the batch bookkeeping use the proposal count. Samples and logZ are identical to v0.2.1; `logl` differs only at the 1e-13 rounding level, from XLA fusing the call inside the branch. Measured on an H100 against v0.2.1: a 13-D mock spectral-siren fit made 55% fewer calls (521k to 233k) and ran 1.8x faster (226 s to 124 s); a 1-D dark-siren fit made 12% fewer calls and ran 1.12x faster. With more than one chain, a `vmap`ped `cond` would evaluate both branches, so nothing is skipped.

## v0.2.1 (2026-09-30)

- On the fast path, closures now get the pytree-callable treatment automatically. A `loglike` or `prior_transform` without array leaves is traced once (`jax.make_jaxpr`), and every jaxpr constant with at least 4096 elements (a captured `jax.Array` or `np.ndarray`, including operands of a nested `jax.jit` call) is passed to the compiled kernels as a jit argument; smaller constants stay embedded. On a 1-D GW likelihood with 2.5M-row arrays (H100), the closure form took two backend compiles of 74 s and 78 s (first block after 172 s), and the pytree form 5.3 s and 6.8 s (first block after 23 s). With hoisting, the same closure reaches its first block after 21.6 s, the same as the pytree form (21.3 s). Through the darksirens ladder harness (a plain closure), a 1-D dark-siren run on the mock R1 fixture dropped from 861 s and 12.0 GB peak RSS to 387 s and 2.2 GB, against dynesty's 679 s. A 4-D real-data run dropped from 4.8 GB to 1.5 GB peak RSS. There is no API change. Closures with only small constants and plain functions are not traced into a new form and give bit-identical results to v0.2.0. A hoisted closure gives the same results as the equivalent `jax.tree_util.Partial`. If tracing fails, the callable keeps closure semantics and one debug-level log message is emitted per callable. Arrays captured inside the body of an inner `jax.jit` function stay embedded. Pytree callables remain the explicit form.
- `walks` now defaults to 12 in 1-D. In a 20-seed sweep, 1-D was unbiased from 10 walks (bias 0.2 x `logzerr`); from 2-D on, the default stays `max(25, 6 * ndim)`.

## v0.2.0 (2026-09-30)

- Added `rwalk_proposal="live-cov"`: each rwalk step is `step_scale * L @ z`, with `L` the Cholesky factor of the live-point covariance in the unit cube. Moves that leave the cube are rejected rather than reflected, and the step scale always adapts toward `rwalk_target_accept`. It is supported for unbounded `sample="rwalk"`, `kernel="jax"` with a fixed `replacement_chains`; other combinations raise `NotImplementedError`.
- **Changed defaults**: `NestedSampler(loglike, prior_transform, ndim).run(key)` and `run_static_nested` now run the fast path: `sample="rwalk"`, `kernel="jax"`, `rwalk_proposal="live-cov"`, `jax_block_size=32`, `walks=max(25, 6 * ndim)` and an initial `step_scale=0.5`. The old defaults were `sample="prior"`, `kernel="python"`, `rwalk_proposal="isotropic"`, `jax_block_size=1`, `walks=25` and `step_scale=0.1`; pass them explicitly to keep the old behavior. The default `kernel="jax"` needs JAX-traceable `loglike` and `prior_transform`.
- Where live-cov is unsupported (`kernel="python"`, a bound, or a `replacement_chain_schedule`), an unset `rwalk_proposal` falls back to `"isotropic"` with `step_scale=0.1` and `jax_block_size=1`, and `sample="prior"` defaults to `kernel="python"`. An explicit `rwalk_proposal="live-cov"` in those combinations still raises.
- Why: the fixed isotropic unit-cube step (`step_scale=0.1`) did not follow the contracting live set, so acceptance collapsed and the cost per iteration grew geometrically at d >= 4. On anisotropic correlated Gaussians, d = 2..18, live-cov keeps the likelihood calls per iteration flat at `walks`. Unbiased evidence needs `walks` of about 5-6 x `ndim`: `walks=25` biased logZ high by +0.5 nats at 13D and +1.4 nats at 18D, while `walks >= 5 * ndim` was within about 0.2 nats, with seed scatter matching the reported `logzerr`.
- With `kernel="jax"`, the initial live points are now evaluated in one compiled pass.
- `loglike` and `prior_transform` may be JAX pytree callables (`jax.tree_util.Partial(loglike_fn, data)`, an equinox-style Module, a registered dataclass with `__call__`). On the fast path (unbounded JAX rwalk: block kernel, per-iteration kernel, rescue draws and the initial live-point pass) their array leaves are passed to the compiled kernels as jit arguments instead of being embedded as constants. On a GW likelihood with 2.5M-row selection arrays (H100) this cut compile time from 76 s to 15 s and peak host RSS from 10.7 GB to 2.8 GB. Detection is automatic; plain functions and closures give bit-identical results to before. Bounded, fused-bounded and `replacement_chain_schedule` kernels keep closure semantics.
- Checkpoints record the resolved `walks`, `step_scale`, `rwalk_proposal` and `jax_block_size`, so a resume with default arguments matches a fresh run with default arguments. Checkpoints without `rwalk_proposal` are read as `"isotropic"` (no format-version bump).
- The benchmark and validation harnesses (`bench_static.py`, `overnight_jax_validation.py`, `validation/run_validation.py`) pin `rwalk_proposal="isotropic"` and `jax_block_size=1` unless a block size is requested, so their configurations are unchanged.

## v0.1.0-alpha

- Narrowed TinyNS public sampler surface to `sample="rwalk"` and `sample="prior"`.
- Removed legacy `slice`, `rslice`, and `sample="bound"` public sampler paths.
- Documented the recommended unbounded isotropic JAX rwalk fast path with `jax_block_size=32`.
- Added cached JAX block rwalk validation summaries and release checklist commands.
- Added optional B16/B32/B64/B128 block-size smoke documentation; B32 remains the default recommendation.
- Added a self-contained 10D GW-like stress-test template with diagnostic figures.
- Added or documented robust block-mode termination behavior for late replacement failures.
- Added a `logzerr` diagnostics breakdown and additional rwalk/replacement telemetry (`repl_ncall`, `repl_chains`, rescue/usage stage counts) to results and metadata.
- Added `NestedSamplingResult.logz_bootstrap(...)` (exported `LogZBootstrap`), a simulated-weights evidence-uncertainty estimator: it jitters the prior-volume shrinkages from their `Beta(nlive, 1)` law over the stored dead-point sequence and recomputes `logz` many times, returning the realization mean, standard deviation, and 16/50/84 percentiles. This captures the skewed prior-volume path uncertainty that the analytic `sqrt(H/nlive)` cannot. It is pure post-processing (no sampler changes) and does not capture sampling bias, so it is a lower bound on true single-run uncertainty when the constrained sampler is under-decorrelated (e.g. an inflated `insertion_rank_mean_z`).
- Added an experimental `rwalk_adaptive_step_scale` JAX-only rwalk option that adapts the isotropic proposal scale from constrained-replacement acceptance telemetry (default off, `step_scale=0.1` unchanged); the acceptance telemetry it adapts from was fixed to reflect true rwalk move acceptance rather than an earlier proxy.
- **Removed** `rwalk_proposal="live-cov"` and `rwalk_cov_jitter`: validation found concerning evidence pulls, and per-axis unit-cube reflection is not symmetry-preserving for correlated proposals. `rwalk_proposal` stays and now accepts only `"isotropic"`; passing anything else raises a clear removal error.
- **Removed** the `replacement_chain_schedule` + `jax_block_size > 1` combination: the in-JIT adaptive kernel evaluated all `max_chains` likelihoods at every stage regardless of schedule position, saving no compute while understating `ncall`/`chains_used` telemetry. Adaptive replacement-chain schedules remain supported at `jax_block_size=1` (the default).
- Fixed block-mode `ncall` undercounting failed-offset and rescue-ladder likelihood calls on an unrescued replacement failure; these are now always counted, matching per-iteration accounting.
- Fixed checkpoint cadence so `checkpoint_interval` is honored in block mode: checkpoints are now written on elapsed nested-iteration deltas rather than an exact-modulo check, so a large `jax_block_size` no longer skips the first several periodic saves (e.g. block 32 / interval 100 previously did not checkpoint before iteration 800).
- Fixed resume labeling: a resumed run that had already converged now reports `success=True, "converged"` instead of an incorrect `"maxiter reached"` message, and a resumed run at or past `maxiter` without convergence is labeled `"maxiter reached"` rather than defaulting to `"converged"`; fixed in both block and per-iteration modes.
- Persisted `effective_step_scale` in checkpoints as an optional `.npz` field (no checkpoint format-version bump; older checkpoints without the field still load) so adaptive step-scale state survives resume; added `rwalk_adaptive_step_scale`/`rwalk_target_accept` config validation on resume.
- Added a warning (not an error) when `NestedSampler` receives unknown keyword arguments; unknown kwargs are still stored, preserving dynesty drop-in compatibility.
- Validated `maxiter >= 1`; a fresh run with `maxiter=0` previously fell through and was mislabeled `"converged"`.
- Deduplicated run-loop state/bound-rebuild helpers, bound-rwalk JAX wrappers, and tuple-based ellipsoid-bound primitives; behavior-preserving, no public API change.
- Kept bounds, fused bounds, and larger block sizes experimental.

## Release caveats

TinyNS v0.1.0-alpha is intended as a small static nested sampler with a validated low-dimensional JAX rwalk fast path. High-dimensional, strongly curved, or multimodal targets require target-specific validation. The included 10D GW-like benchmark is a stress test for constrained-replacement mixing, not a production GW parameter-estimation pipeline.
